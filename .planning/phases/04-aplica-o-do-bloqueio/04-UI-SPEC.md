# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** three UI surfaces only — (1) the grace-period banner inside the admin shell, (2) the dedicated blocked screen at `/[slug]/admin/bloqueado`, (3) the generic-branding variant of the existing admin login page (D-09). Everything else in this phase is server-side enforcement with no visual output.

**Prime directive:** this phase adds the project's *first* alert/banner pattern (confirmed by grep in `04-CONTEXT.md` §Established Patterns). It must be assembled from the visual language already present in `app/[slug]/admin/**`, not from a new design system. Every token below was extracted from existing code, not invented.

## Spacing Scale

Base unit 4px (Tailwind 4 default `--spacing`). Declared values (all multiples of 4):

| Token | Value | Tailwind | Usage in this phase |
|-------|-------|----------|---------------------|
| xs | 4px | `1` / `gap-1` | Gap between stacked micro-labels |
| sm | 8px | `2` / `gap-2` | Icon-to-text gap inside the inline error block |
| md | 12px | `3` / `gap-3` | Icon-to-text gap in the banner; button row gaps |
| lg | 16px | `4` / `p-4` | Banner internal padding; full-screen shell padding |
| xl | 24px | `6` / `mb-6` | Banner-to-content separation; card section breaks |
| 2xl | 32px | `8` / `p-8` | Blocked-screen card internal padding |
| 3xl | 48px | `12` | Reserved — not used by this phase |

**Vertical rhythm rules (binding):**
- Banner sits at the very top of the `<main>` content region with `mb-6` (24px) below it. No margin above — `<main>` already provides `p-6`.
- Blocked-screen card: `p-8` (32px) inside, sections separated by `mb-4` (16px) / `mb-6` (24px).
- Button stacks separate with `mt-3` (12px).

**Exceptions:** two, both pre-existing and inherited, neither introduced by this phase:
1. `app/[slug]/admin/_components/login-form.tsx` uses `py-2.5` (10px) and `mb-1.5` (6px) on its inputs and labels. This phase touches that file's *data* only (D-09 branding values); its class strings are untouched.
2. `app/[slug]/admin/login/page.tsx` uses `h-2` (8px, a multiple of 4 — fine) for the gradient bar. Retained.

**New markup in this phase must not introduce any non-multiple-of-4 spacing value.**

**Minimum touch target:** every button in this phase is ≥ 44px tall. With `text-sm` (20px line box), `py-3` (12px + 12px) yields exactly 44px. `py-2.5` yields 40px and is **forbidden on buttons** in the three new/edited surfaces.

## Typography

Three sizes, two weights. Line heights are declared as ratios and implemented with Tailwind 4's line-height modifier (`text-sm/[1.5]`).

| Role | Size | Weight | Line Height | Tailwind | Where |
|------|------|--------|-------------|----------|-------|
| Body | 14px | 400 (`font-normal`) | 1.5 | `text-sm/[1.5]` | Banner message, blocked-screen explanation, all button labels (buttons override to 600) |
| Label | 12px | 600 (`font-semibold`) | 1.33 | `text-xs` | Inline error text, secondary meta line |
| Heading | 20px | 600 (`font-semibold`) | 1.2 | `text-xl/[1.2]` | Banner title, blocked-screen `<h1>` |
| Display | — | — | — | — | **Not used in this phase** — no surface here warrants display type |

**Button labels** are `text-sm font-semibold` (14px / 600) — matching `login-form.tsx:71` exactly.

**Legacy weight carve-out (one, documented):** `app/[slug]/admin/login/page.tsx:50` renders its `<h1>` at `font-bold` (700). D-09 changes the *string* inside that heading, not its class. Leaving the class alone keeps the D-09 diff data-only and avoids restyling a working page. **No new markup in this phase may use weight 500 or 700.**

**Rationale for 400+600:** the codebase histogram is `font-semibold` 126 × `font-bold` 45 × `font-medium` 28 — semibold is the established emphasis weight. Body copy in the codebase carries no weight class, i.e. 400.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f8fafc` (`slate-50`) | Page background of the admin shell and of both full-screen surfaces (login, blocked) |
| Secondary (30%) | `#ffffff` (`white`) | Cards, sidebar, top bar, blocked-screen card |
| Accent (10%) | tenant `empresa.primaryColor`, fallback `#18181b` | See reserved list below |
| Warning (semantic) | amber ramp — surface `#fffbeb` (`amber-50`), border `#fde68a` (`amber-200`), fill `#d97706` (`amber-600`), icon `#f59e0b` (`amber-500`), heading `#78350f` (`amber-900`), body `#92400e` (`amber-800`) | Grace banner **only**; blocked-screen status icon tile |
| Error (semantic) | red ramp — surface `#fef2f2` (`red-50`), border `#fecaca` (`red-200`), icon `#ef4444` (`red-500`), text `#dc2626` (`red-600`) | The `?erro=checkout` failure message **only** |
| Destructive | **not used** | This phase has no destructive action — see Copywriting Contract |

**Text colors** (inherited, unchanged): `slate-800` primary text, `slate-600` form labels, `slate-500` secondary/body, `slate-400` tertiary, `slate-200` control borders, `slate-100` card borders.

### Accent reserved for — explicit list

Tenant `primaryColor` may be applied to **exactly these four things** in this phase:

1. The `background` of the blocked screen's primary "Pagar agora" button.
2. The `--tw-ring-color` focus ring of that same button.
3. The 8px gradient bar at the top of the blocked-screen card (`linear-gradient(90deg, primaryColor, accentColor)`), mirroring `login/page.tsx:26-31`.
4. Nothing else.

**Accent is explicitly NOT used for:** the grace banner's CTA, the banner surface or border, the logout button, body text, any border in the banner, or any element on the blocked-branding login variant (D-09 forbids tenant color there entirely).

### Why the banner CTA is amber-600, not tenant accent

`empresa.primaryColor` is a free-form user-supplied hex with no contrast validation anywhere in the system. Placing an arbitrary tenant color on an `amber-50` surface risks an invisible button on the one control that has to convert. `amber-600` on `amber-50` is a fixed, known-good pairing and reads as "this belongs to the warning". The blocked screen, by contrast, is a white card where the tenant button repeats a pattern the user just used to log in.

**Inherited contrast risk (out of scope, do not "fix" here):** a tenant that picks a pale `primaryColor` already gets white-on-pale text on the login submit button today. This phase reproduces that existing pattern on the blocked screen; validating tenant color contrast is a separate concern.

## Copywriting Contract

Tone, locked by `04-CONTEXT.md` §Claude's Discretion: *"mensagens diretas em português"*, matching the existing register of `"Sessão inválida."` / `"Entrar no painel"` / `"Autenticando..."`. Second person, no exclamation marks, no apology, no jargon, no gateway name.

| Element | Copy |
|---------|------|
| Primary CTA | **`Pagar agora`** (locked by D-01) — identical string on both the banner and the blocked screen |
| Primary CTA pending state | `Redirecionando...` (mirrors `Autenticando...` in `login-form.tsx:74`) |
| Secondary CTA (blocked screen) | `Sair da conta` |
| Empty state heading | **Not applicable — and deliberately forbidden.** The one "nothing here" surface this phase produces is the public catalogue of a blocked company, which must render the framework's default 404 with **no custom copy, no heading, no illustration and no mention of payment** (D-07). Any empty-state copy added there is a contract violation, not a nicety. |
| Empty state body | See above — none. |
| Error state | `Não foi possível abrir o pagamento agora. Tente novamente em alguns instantes.` (rendered on `/[slug]/admin/bloqueado?erro=checkout`; gateway detail goes to `console.error` only, per CLAUDE.md §Error Handling) |
| Destructive confirmation | **None — this phase has no destructive action.** `Sair da conta` ends a session and is fully reversible by logging back in; the existing logout controls (`admin-nav.tsx:114`, `simples-top-bar.tsx:45`) use no confirmation, and adding one here would be inconsistent. Do **not** wire `ConfirmSubmitButton` to it. |

### Grace banner copy (ACC-01)

Title: **`Pagamento pendente`**

Body, selected by `diasRestantes` (server-computed, see Component Contracts):

| `diasRestantes` | Body copy |
|-----------------|-----------|
| `>= 2` | `Seu acesso vence em {n} dias. Depois disso, o painel e o catálogo da sua loja saem do ar.` |
| `1` | `Seu acesso vence amanhã. Depois disso, o painel e o catálogo da sua loja saem do ar.` |
| `0` | `Seu acesso vence hoje. Depois disso, o painel e o catálogo da sua loja saem do ar.` |

The catalogue warning is included because it is true (ACC-03) and it is the strongest honest motivator available. It appears **only** in the admin — never on the public catalogue (D-02).

### Blocked screen copy (ACC-02)

Heading: **`Acesso suspenso`**

Body: **`O painel da sua loja está suspenso por falta de pagamento, e o catálogo saiu do ar. Assim que o pagamento for confirmado, tudo volta automaticamente.`**

**One string for both statuses.** `BLOQUEADO` and `CANCELADO` render byte-identical copy — D-06 forbids any differentiated message for voluntary cancellation. The executor must not branch on status for copy purposes.

`volta automaticamente` is a factual claim backed by ACC-04/D-08 (`revalidarConta` re-derives status every request; the Phase 3 webhook extends `acessoAte`). Do not soften it to "entre em contato" — there is nothing to contact.

### Generic-branding login copy (D-09)

When the company is blocked, `app/[slug]/admin/login/page.tsx` renders:

| Element | Normal (unchanged) | Blocked variant |
|---------|-------------------|-----------------|
| `<h1>` | `{empresa.nome}` | `Painel Administrativo` |
| Subtitle `<p>` | `Painel Administrativo` | **omitted** (the heading absorbed it) |
| Logo tile | `empresa.logo` image, else `empresa.nome.charAt(0)` | generic padlock glyph (path already on this page, `login/page.tsx:65`) |

## Component Contracts

### 1. `AvisoCarencia` — grace banner

**Props (server-computed, no clock inside the component):**

```ts
{
  diasRestantes: number;              // >= 0, already clamped
  pagarAction: () => Promise<void>;   // iniciarPagamento.bind(null, slug)
}
```

`diasRestantes` is derived by the layout from `ContaAtiva.carenciaAte` using `meiaNoiteEmSaoPaulo` (`lib/fuso-sao-paulo.ts`), rounded **in the user's favour** (ceil) and clamped to `>= 0`. **`new Date()` must never appear inside this component** (Pitfall 5) — keeping the component a pure function of a number is what makes it testable without fake timers, matching the injected-clock convention established in Phase 2.

**Structure:**

```
<section role="status" class="mb-6 flex flex-wrap items-center gap-3
                              rounded-2xl border border-amber-200 bg-amber-50 p-4">
  <svg h-5 w-5 shrink-0 text-amber-500 />          ← warning triangle
  <div class="min-w-0 flex-1">
    <p class="text-xl/[1.2] font-semibold text-amber-900">Pagamento pendente</p>
    <p class="mt-1 text-sm/[1.5] text-amber-800">{body copy}</p>
  </div>
  <form action={pagarAction} class="w-full sm:w-auto">
    <PagarButton variant="banner" />               ← client, useFormStatus
  </form>
</section>
```

**Binding rules:**
- **Not dismissible.** No close button, no `localStorage`, no state. ACC-01 requires it on *every* admin screen; a dismiss control defeats the requirement.
- `role="status"` (polite), **not** `role="alert"` — a persistent advisory banner must not interrupt assistive-tech users on every page load.
- Radius `rounded-2xl` matches the card radius already used by `StatCard` (`(protected)/page.tsx:25`).
- Responsive: `flex-wrap` + `w-full sm:w-auto` on the CTA form — the button drops to full width below 640px rather than crushing the text.
- Rendered **above** `{children}` inside `<main>`, in both branches of `(protected)/layout.tsx`.
- **Never imported anywhere under `app/[slug]/(catalogo)`** (D-02) — enforce with the grep gate already listed in `04-RESEARCH.md` §Validation Architecture.

**Known limitation (accepted, documented):** App Router partial rendering means layouts do not re-render on client-side `<Link>` navigation, so `diasRestantes` can go stale within a session (Pitfall 4). This is acceptable because the banner is advisory — the authorisation boundary is `requireAdminSession` on every page — and because the Asaas `successUrl` is a full document navigation back to `/{slug}/admin`, which re-renders the layout. Do **not** add polling or a client timer to "fix" this.

### 2. `PagarButton` — shared payment CTA

Client component (`"use client"`), consumes `useFormStatus()` from `react-dom`. Used inside a `<form action={iniciarPagamento.bind(null, slug)}>` in both surfaces.

| Variant | Classes | Inline style |
|---------|---------|--------------|
| `banner` | `w-full rounded-xl bg-amber-600 px-4 py-3 text-sm font-semibold text-white shadow-md transition-all hover:bg-amber-700 hover:shadow-lg active:scale-[0.98] disabled:opacity-60 sm:w-auto` | none |
| `bloqueado` | `w-full rounded-xl py-3 text-sm font-semibold text-white shadow-md transition-all hover:shadow-lg active:scale-[0.98] disabled:opacity-60` | `{ backgroundColor: primaryColor }` |

Label: `Pagar agora` → `Redirecionando...` while `pending`, `disabled={pending}`. The `bloqueado` variant's class string is character-identical to `login-form.tsx:71` — deliberate reuse, not coincidence.

`useFormStatus` (not `useActionState`) because the action returns `void` and terminates in a `redirect()`; there is no state to render.

### 3. Blocked screen

**Shell** mirrors the login page so the user recognises the surface they just came through:

```
<div class="flex min-h-screen items-center justify-center bg-slate-50 p-4">
  <div class="w-full max-w-md">                     ← max-w-md (448px), not max-w-sm:
    <div class="overflow-hidden rounded-3xl                more copy than the login card
                border border-slate-100 bg-white shadow-xl">
      <div class="h-2" style={gradient(primaryColor, accentColor)} />

        <div class="mx-auto mb-4 flex h-16 w-16 items-center justify-center

        <p class="mt-2 text-center text-sm/[1.5] text-slate-500">{body copy}</p>

        {erro === "checkout" && <InlineError />}    ← see below

        <form action={pagarAction} class="mt-6">
```

The amber icon tile deliberately ties this screen to the banner: the user sees the same warning colour escalate from a strip to a full screen.

## Accessibility

- Banner: `role="status"` (polite live region), never `role="alert"`.
- Blocked screen: exactly one `<h1>` (`Acesso suspenso`). The page has no nav landmark by design.
- Every button is a real `<button type="submit">` inside a `<form action={...}>` — no `<div onClick>`, consistent with the project's zero-`fetch` Server Action model.
- Minimum touch target 44×44px on every button (`py-3` + `text-sm`).
- Colour is never the sole carrier of meaning: the banner pairs amber with the word `Pagamento pendente` and a warning glyph; the error block pairs red with an explicit sentence.
- Contrast: `amber-900` on `amber-50` and `amber-800` on `amber-50` both exceed 7:1; `slate-500` on `white` exceeds 4.5:1; white on `amber-600` exceeds 4.5:1 at 14px semibold.
- The generic-branding login variant keeps its `<label>`/`htmlFor` associations untouched.
